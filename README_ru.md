# Расширение для интеграции с Reindexer

Это расширение позволяет интегрировать документационные проекты, управляемые Foliant, с СУБД [Reindexer](https://github.com/Restream/reindexer/), работающей в оперативной памяти, для использования её в качестве поискового движка.

Основная часть расширения — это препроцессор, который подготавливает данные для поискового индекса. Кроме того, препроцессор выполняет базовые манипуляции с базой данных и пространством имён в ней.

Также расширение предоставляет простой рабочий пример клиентского веб-приложения, которое может использоваться для выполнения поиска. Редактируя HTML, CSS и JS код, вы можете настроить его в соответствии с вашими потребностями.

## Установка

Чтобы установить препроцессор, выполните команду:

```bash
$ pip install foliantcontrib.reindexer
```

Чтобы использовать пример клиентского веб-приложения для поиска, скачайте [эти HTML, CSS и JS файлы](https://github.com/foliant-docs/foliantcontrib.reindexer/tree/master/webapp_example/) и откройте файл `index.html` в вашем веб-браузере.

## Конфигурация

Чтобы включить препроцессор, добавьте `reindexer` в секцию `preprocessors` в конфигурации проекта:

```yaml
preprocessors:
    - reindexer
```

Препроцессор имеет ряд опций со следующими значениями по умолчанию:

```yaml
preprocessors:
    - reindexer:
        reindexer_url: http://127.0.0.1:9088/
        insert_max_bytes: 0
        database: ''
        namespace: ''
        namespace_renamed: ''
        fulltext_config: {}
        actions:
            - drop_database
            - create_database
            - create_namespace
            - insert_items
        use_chapters: true
        format: plaintext
        escape_html: true
        url_transform:
            - '\/?index\.md$': '/'
            - '\.md$': '/'
            - '^([^\/]+)': '/\g<1>'
        require_env: false
        targets: []
        split_by_headers: false
        split_headers_level: 2
        min_section_length: 100
        keep_original: false
```

`reindexer_url`
:   URL вашего экземпляра Reindexer. Здесь должен использоваться "корневой" URL сервера, не добавляйте к нему никаких конечных точек, таких как `/api/v1/db`.

`insert_max_bytes`
:   Reindexer или прокси-сервер может ограничивать допустимый размер тела запроса. Используйте эту опцию, если необходимо разбить большой объем контента для индексации на несколько частей, чтобы каждая из них отправлялась отдельным запросом. Значение этой опции представляет максимальный размер тела HTTP POST запроса в байтах. Допустимые значения — положительные целые числа от `1024` и `0` (по умолчанию), что означает отсутствие ограничений.

`database`
:   Имя базы данных, которая используется для хранения вашего поискового индекса.

`namespace`
:   Имя пространства имён в указанной базе данных. Пространство имён в Reindexer означает то же самое, что таблица в реляционных базах данных. Для хранения поискового индекса одного документационного проекта достаточно одного пространства имён.

`namespace_renamed`
:   Новое имя пространства имён, которое будет применено при использовании действия `rename`; см. ниже.

`fulltext_config`
:   Значение поля `config`, которое относится к описанию составного полнотекстового индекса по полям данных `title` и `content`. Используемая структура данных описана ниже. [Опции конфигурации полнотекстовых индексов](https://reindexer.io/reindexer-docs/select/text/#params_management) перечислены в официальной документации Reindexer.

`actions`
:   Последовательность действий, которые должен выполнить препроцессор. Доступные значения элементов:

* `drop_database` — полностью удалить базу данных, указанную в опции `database`. Пожалуйста, будьте осторожны при использовании этого действия, когда одна база данных используется для хранения нескольких пространств имён. Поскольку это действие включено в список действий по умолчанию, рекомендуется использовать отдельные базы данных для каждого поискового индекса. Список действий по умолчанию предполагает, что в большинстве случаев необходимо удалить, а затем полностью перестроить индекс, при этом база данных и пространство имён могут не существовать;
* `create_database` — создать новую базу данных с именем, указанным в опции `database`;
* `drop_namespace` — удалить пространство имён, указанное в опции `namespace`. Все действия `*_namespace` применяются к существующей базе данных с именем из опции `database`;
* `truncate_namespace` — удалить все элементы из пространства имён, указанного в опции `namespace`, но сохранить само пространство имён;
* `rename_namespace` — переименовать существующее пространство имён с именем, указанным в опции `namespace`, в новое имя из опции `renamed_namespace`. Это действие может быть полезно, когда общий поисковый индекс создаётся для нескольких проектов Foliant, и индекс может оставаться неполным в течение длительного времени при их сборке;
* `create_namespace` — создать новое пространство имён с именем из опции `namespace`;
* `insert_items` — заполнить пространство имён, указанное в опции `namespace`, контентом, который должен быть проиндексирован. Каждый элемент данных, добавляемый в пространство имён, соответствует отдельной секции Markdown (или файлу, в зависимости от настроек).

`use_chapters`
:   Если установлено в `true` (по умолчанию), препроцессор применяется только к файлам, которые упомянуты в секции `chapters` конфигурации проекта. В противном случае препроцессор применяется ко всем Markdown-файлам проекта.

`format`
:   Формат, в который исходное Markdown-содержимое должно быть преобразовано перед добавлением в индекс; доступные значения: `plaintext` (по умолчанию), `html`, `markdown` (без преобразования).

`escape_html`
:   Если установлено в `true` (по умолчанию), конструкции синтаксиса HTML в содержимом, преобразованном в `plaintext`, будут экранированы заменой `&` на `&amp;`, `<` на `&lt;`, `>` на `&gt;` и `"` на `&quot;`.

`url_transform`
:   Последовательность правил для преобразования локальных путей исходных Markdown-файлов в URL целевых страниц. Каждое правило должно быть словарём. Его данные передаются в метод [`re.sub()`](https://docs.python.org/3/library/re.html#re.sub): ключ как аргумент `pattern`, значение как аргумент `repl`. Локальный путь (возможно, ранее преобразованный) к исходному Markdown-файлу относительно временной рабочей директории передаётся как аргумент `string`. Когда включена опция `split_by_headers`, препроцессор автоматически добавляет якоря к URL (например, `page.html#section-anchor`). Значение опции `url_transform` по умолчанию предназначено для использования со статическими веб-сайтами  MkDocs.

`require_env`
:   Если установлено в `true`, переменная окружения `FOLIANT_REINDEXER` должна быть задана, чтобы разрешить препроцессору выполнять какие-либо операции с базой данных и пространством имён, управляемыми Reindexer. Этот флаг может быть полезен в задачах CI/CD.

`targets`
:   Допустимые цели для препроцессора. Если не указано (по умолчанию), препроцессор применяется ко всем целям.

`split_by_headers`
:   Если установлено в `true`, препроцессор разбивает каждый Markdown-документ на секции по заголовкам указанного уровня. Каждая секция становится отдельным элементом поискового индекса со своим собственным URL (включая якорь) и заголовком. Это улучшает точность поиска, позволяя пользователям переходить непосредственно к релевантным разделам вместо целых документов. По умолчанию: `false`.

`split_headers_level`
:   Определяет, заголовки какого уровня использовать для разбиения документов, когда включена опция `split_by_headers`. Допустимые значения: от `1` до `6`. Например, `2` означает разбиение по заголовкам `<h2>` (`##` в Markdown). По умолчанию: `2`.

`base_url`
:   Добавляется в начало `url`. Может быть полезен, если требуются абсолютные ссылки. Например, если `base_url: https://example.com`, то все URL станут абсолютными: `https://example.com/section/file`.

`doc_type`
:   Тип документа может быть задан через параметр препроцессора или через переменную окружения `REINDEXER_DOC_TYPE`. Если не задан, используется `title`, указанный в конфигурационном файле проекта.

`use_strip_markdown`
:    Включить удаление Markdown-разметки из содержимого.

`preserve_code_blocks`
:    Сохранять содержимое кодовых блоков, а не заменять его на заглушку.

`preserve_links_text`
:   Сохранять видимый текст ссылок, а не удалять его полностью.

## Использование

Препроцессор читает каждый исходный Markdown-файл и подготавливает три поля для индексации:

* `url` — URL целевой страницы. Это поле используется как первичный ключ, поэтому оно должно быть уникальным;
* `title` — заголовок документа, берётся из первого заголовка исходного Markdown-содержимого;
* `content` — исходное Markdown-содержимое, опционально преобразованное в обычный текст или HTML.

Когда все файлы обработаны, препроцессор вызывает API Reindexer для вставки элементов данных (каждый элемент соответствует одному Markdown-файлу) в указанное пространство имён.

### Разбиение документа по заголовкам

Когда включена опция `split_by_headers: true`, препроцессор интеллектуально разбивает каждый документ на секции на основе уровней заголовков:

- **Извлечение секций**: Документ делится везде, где появляется заголовок указанного уровня (`split_headers_level`).
- **Якоря URL**: Каждая секция получает URL с уникальным якорем (например, `page.html#level2-configuration`), что позволяет делать прямые ссылки.

#### Пример: Разбиение по заголовкам H2

Дан Markdown-файл:

```markdown
# Главный заголовок

## Установка
Шаги установки...

## Конфигурация
Детали конфигурации...

### Расширенные настройки
Вложенный подзаголовок (не точка разбиения)
```

С настройками `split_by_headers: true` и `split_headers_level: 2` создаются две записи индекса:
- Запись 1: URL `page.html#level2-установка`, Заголовок `"Установка"`, Содержимое `"Шаги установки..."`
- Запись 2: URL `page.html#level2-конфигурация`, Заголовок `"Конфигурация"`, Содержимое `"Детали конфигурации...\n\n### Расширенные настройки\nВложенный подзаголовок..."`

Заголовок H3 включается как часть содержимого секции H2.

#### Особенности производительности

Разбиение документов по заголовкам:
- Увеличивает количество записей индекса (по одной на секцию)
- Требует больше места для хранения
- Использует больше памяти во время индексации
- Значительно улучшает точность поиска и пользовательский опыт

Настройте `insert_max_bytes`, если вы сталкиваетесь с ограничениями размера запроса при индексации множества секций.

### Манипуляции с базой данных и пространством имён

Препроцессор может вызывать API Reindexer для манипуляции базой данных или пространством имён, например, для удаления ранее созданного поискового индекса. Последовательность действий управляется опцией `actions`.

### Выполнение поисковых запросов

Вы можете выполнять пользовательские поисковые запросы к API Reindexer.

[Простой пример клиентского веб-приложения](https://github.com/foliant-docs/foliantcontrib.reindexer/tree/master/webapp_example/), который предоставляется как часть этого расширения, отправляет в Reindexer запросы, подобные этому:

```json
{
    "namespace": "testing",
    "filters": [
        {
            "field": "indexed_content",
            "cond": "EQ",
            "value": "@title^3,content^1 foliant"
        }
    ],
    "select_functions": [
        "content = snippet(<em>,</em>,100,100,'\n\n')"
    ],
    "limit": 50
}
```

Чтобы узнать, как писать эффективные запросы к Reindexer, вам может потребоваться обратиться к его официальной документации по темам: [общее использование](https://reindexer.io/reindexer-docs/), [полнотекстовый поиск](https://reindexer.io/reindexer-docs/select/text/), [HTTP REST API](https://github.com/Restream/reindexer/blob/master/cpp_src/server/contrib/server.md).

В приведённом выше примере поле `indexed_content` соответствует составному индексу по двум полям: `title` и `content` (этот индекс создаётся при создании пространства имён запросом от препроцессора). [Текст поискового запроса](https://reindexer.io/reindexer-docs/select/text/#fulltext_queries_format) начинается с `@title^3,content^1`, что означает, что поле `title` составного индекса имеет тройной приоритет (т.е. весовой коэффициент 3), а поле `content` имеет нормальный приоритет (т.е. весовой коэффициент равен 1). Также в примере используется [функция выборки](https://reindexer.io/reindexer-docs/select/text/#использование-функций-для-модификации-результатов-поиска) `snippet()` для подсветки текста, соответствующего запросу, и для обрезки лишнего.

Если вы используете самостоятельно размещённый экземпляр Reindexer, вам может потребоваться настроить прокси для добавления заголовков [CORS](https://developer.mozilla.org/ru/docs/Web/HTTP/CORS) к ответам HTTP API.
